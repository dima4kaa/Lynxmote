# Lynxmote

Десктоп-приложение для мониторинга и управления серверами Proxmox VE: живая таблица нод, VM и контейнеров, предупреждения, виджеты и терминал. C# / .NET 10 / Avalonia.

До версии 1.7.0 приложение называлось ProxMonitor. Настройки из `%AppData%\ProxMonitor` переносятся в `%AppData%\Lynxmote` сами при первом запуске.

## Запуск

```
dotnet run --project Lynxmote.App
```

Без сервера: кнопка **«Открыть демо»** или `dotnet run --project Lynxmote.App -- --demo`.

## Подключение к Proxmox

1. В веб-интерфейсе Proxmox: **Datacenter → Permissions → API Tokens → Add**. Скопируйте секрет: он показывается один раз.
2. Выдайте токену права: **Datacenter → Permissions → Add → API Token Permission**, путь `/`, ваш токен, роль `PVEAuditor` (для запуска и остановки VM добавьте ещё `PVEVMUser`). Без этого шага токен с галочкой «Privilege Separation» (она включена по умолчанию) видит только имя ноды: без нагрузки и без списка VM.
3. В приложении: **«Подключить сервер»** → адрес `https://<IP>:8006`, Token ID `user@realm!имя`, секрет.
4. Сверьте отпечаток сертификата с **Нода → System → Certificates** и подтвердите.

Температуру, сетевой трафик и число подключений ноды API Proxmox не отдаёт, их приложение читает по SSH. Нажмите **«войти»** на карточке ноды (или ПКМ → **Вход по SSH…**) и войдите один раз: логин сохранится, и дальше приложение опрашивает ноду само при каждом запуске. Нужен датчик в `/sys/class/hwmon` (lm-sensors ставить не обязательно).

Пароль можно не вводить, если сервер пускает по SSH-ключу этого компьютера: приложение пробует `id_ed25519`, `id_ecdsa` и `id_rsa` из папки `.ssh` в профиле пользователя (ключ с парольной фразой не подойдёт). Отпечаток ключа сервера при первом входе всё равно нужно подтвердить.

Заполненность диска и IP-адрес виртуальной машины Proxmox узнаёт только через **qemu-guest-agent**. Если агента нет, приложение читает их по SSH прямо из VM: в столбце «Диск» появляется кнопка **«войти»**, по ней открывается окно с адресом, логином и паролем VM. Войти нужно один раз, дальше VM опрашивается сама. Адрес приложение старается подсказать (по сетевой карте VM, если нода с ней недавно общалась); если не получилось, введите его вручную. Так работают VM с Linux, доступные по сети с этого компьютера. VM с Windows без агента остаются с «—»: им нужен агент (драйверы virtio и **VM → Options → QEMU Guest Agent**). Контейнерам (LXC) ничего из этого не нужно.

**Терминал** VM без агента подключается по SSH прямо к самой VM: при первом открытии введите её адрес и логин, они сохранятся. После этого работают и активные подключения в «Свойствах». VM должна быть доступна по сети с этого компьютера.

## Если что-то не работает

Меню **Lynxmote → Журнал диагностики** покажет файл `lynxmote.log` (лежит в `%AppData%\Lynxmote`). В нём ответы сервера, ошибки подключения и SSH. Секретов токена и паролей там нет. Пришлите этот файл тому, кто разбирается с проблемой.
